# Mnema 現行UI・操作仕様

確認日: 2026-09-21

Asanaの画面構成、ClickUpのタスク行、Notion Calendarのカレンダー、ログイン済みReclaimの習慣登録・予定詳細を参考に、デスクトップ全体を更新しました。

## ホームと共通操作

- 上部に日付と時間帯別の挨拶を表示。リード文とメモ帳は非表示にしました。既存のメモファイルは削除しません。
- 横幅に余裕がある場合は左にカレンダー、右にマイタスクを約1:2で配置し、両ウィジェットを画面下端まで伸ばします。内容は各ウィジェット内でスクロール。狭い画面では縦並びです。
- 左メニューはホーム、受信トレイ、タスク、プロジェクト、スケジュール、習慣、アシスタント、設定。
- 右上のテーマ切替は、ホバー時に横へ広がり、押下時に縮み、つまみが移動するトグル。領域を事前に確保するので周囲の配置は動きません。テーマ、行間、並び順、グループ化を保存します。
- テーマ変更時だけ全体のStyleを更新。従来の毎フレームのStyle再構築・全色補間を廃止しました。共通部品は `crates/desktop/src/gui/components.rs` にまとめ、アイコンボタン・タブ・新しい操作ボタンのホバー時間、押下時間、トグル時間を調整できます。実機でのFPS比較は行っていません。
- Refreshボタンを廃止。画面切替、フォーカス復帰、約15秒ごとに読み直します。入力中、メニュー表示中、ドラッグ中、タスク詳細・予定時刻・習慣フォームの編集中は保留し、未保存の計画案や入力内容を維持します。
- ボタン・入力欄の角丸と基本サイズ、メニューの内側余白・行高・ホバー表現を `components.rs` に統一。表示設定の歯車、習慣の操作、入力欄の所属指定も共通アイコンボタンを使用します。ドロップダウンとサブメニューは共通のメニュースタイルです。

## タスク

- ホーム・タスク・プロジェクトで同じタスク行と入力欄を使用。
- ステータス、タイトル、所属、期限、見積時間、算出した優先度を表示。十分な横幅がある場合はマイルストーンもチップ表示します。
- 未着手は破線の円、進行中は大きめの内円、保留は横線、完了は塗りつぶしたチェック。
- 状態アイコンのクリックで色付きのステータスメニューを開きます。ここから状態変更できます。
- ドラッグは専用ハンドルまたはタイトルから開始。ポインターの横に小さなプレビューを表示し、行全体が中央へ飛ぶ挙動を修正しました。
- 期限・見積時間は常時同じ位置に表示し、クリックすると行内ポップアップで変更できます。ホバー時には完了ボタンが現れます。操作メニューから所属変更・コピー・削除、横幅がある場合は所属表示から直接変更できます。背景と共通ボタンに短いアニメーションを付けています。
- タイトルをクリックすると中央に詳細を表示します。開いた直後は閲覧表示で、タイトル・説明をクリックしたときだけ入力欄へ切り替わります。状態・期限・見積時間・所属・マイルストーンは各項目から直接変更。完了済みタスクも対象です。期限・見積時間と所属の変更では詳細画面を開きません。
- 日付ピッカーはClickUpの実画面を参照し、上部に日付入力、左に今日／明日／今週末／来週／来週末／2週間後／4週間後と補助日付、右に月カレンダーを配置。区切り線、余白、月送り・今月ボタン、今日・選択日・ホバーの表示を整理しました。日付の直接入力とクリアにも対応。`date_picker.rs` をタスク行・詳細・新規タスク・プロジェクト・マイルストーンで共用します。
- 見積時間もタスク行・詳細・新規タスクで同じ候補選択と `1h30m` 等の入力・クリアを使用。既存タスクの行内変更は選択時に保存し、古い更新日時による上書きを拒否します。新規タスク・プロジェクトの日付選択は作成前の入力として保持します。タスクの項目部品は `task_fields.rs`。
- ホバーで完了ボタンが現れたときに内部の入力IDが変わる不具合を修正しました。一瞬表示されていた赤枠はeguiの診断表示で、データ保存エラーではありません。非表示時も同じ配置とIDを維持します。
- Doneで行が消えて次のタスクが繰り上がる場合も、外側の配置とタスクIDに紐づく内部部品を分けて保持します。日付別・ステータス別、複数行・最後の1行の完了で赤い診断線が出ないことを検証しました。
- 起動後の最初のDoneで画面全体に赤い枠が出る別条件も修正。更新メッセージの下部パネルが初めて追加されるとメイン画面の自動IDがずれ、1回の描画で34個の診断枠が発生していました。メイン画面を独立した固定IDの領域にし、パネルの出入りから分離しています。前のテストは準備用タスクの作成メッセージが最初から表示されていたため、起動直後を再現できていませんでした。
- すべて／今日／期限超過／完了、検索、並び順、行間を切り替えられます。歯車の「グループ化」で日付・予定別／ステータス別を切り替えます。
- 日付・予定別は「今日・期日超過・次・スケジュール未設定」。過去の期限を最優先で期日超過に分類し、今日が期限または今日に有効な予定があれば今日、未来の期限・予定は次、どちらもない場合は未設定。現在表示中の月より先の予定も参照し、完了・取消・未実施の予定は未来の予定として数えません。
- Mnemaがアクティブなときに `Ctrl+T`、または追加欄の＋からタスク作成ポップアップを開きます。ClickUpの実アプリを参照し、所属リスト、大きなタイトル欄、説明欄、アイコン付きの設定、右下の作成ボタンを配置しました。`Ctrl+Enter`で保存し、「続けて作成」で連続登録できます。閉じた下書きはアプリ起動中に保持し、再度開くと再開します。
- 既存の追加欄と作成ポップアップでスラッシュメニューを共用。末尾の `/` から期日・今日／明日の期限・見積時間・ステータス・所属リストを選べます。日本語／英語で検索、↑↓で選択、Enter／Tabで適用、Escでメニューだけを閉じます。期日・見積時間は候補に加えて日付や `1h30m` の直接入力も可能です。URLやファイルパスの `/` では開きません。
- 通常の追加欄はEnterまたは送信アイコンで追加。スラッシュメニュー選択中のEnterは登録を行いません。選んだ値は設定ボタンに反映され、同じ日付・見積ピッカーでも調整できます。作成時のステータスは保存先で使えるものか検証してから登録します。
- 入力例: `企画書を作る /due tomorrow /minutes 45`。
- プロジェクト内の追加はそのプロジェクトのリストへ直接保存します。存在しない保存先で失敗してもInboxにタスクを残しません。
- 優先度は期限から算出し、保存フィールドを追加していません。独立したタグ機能は未実装で、既存の所属・マイルストーンを使用しています。

| --- | --- |

| スケジュール | 日・2〜9日・週・月表示。計画メニューから対象期間を選択し、提案・適用・未保存の提案の破棄。予定をクリックして詳細、日時編集、完了／予定へ戻す、固定／自動配置へ戻す、取消。 |
| 習慣 | ギャラリー／優先度別／テンプレート。専用フォームで名前、必須／柔軟、毎日／曜日指定、所要時間、時間帯を設定し保存。既存設定の編集、発生分のスキップ・24時間延期、習慣の停止。 |
| 受信トレイ | 実際のAutomationLogを一覧・詳細で表示。すべて／未読、既読化、未読に戻す、対象タスクを開く。既読状態は端末の設定に保存。 |
| アシスタント | 会話表示、入力候補、Ctrl+Enterで送信、モデル設定への導線。タスク作成と次アクションの確認が中心。 |
| 設定 | 外観／時間・計画／カレンダー連携／アシスタント／データ・接続に分類。設定を保存し、保存先の変更時は再接続。 |

## カレンダーと習慣の表示

- カレンダーはホーム・スケジュールで共通。上部の操作は一列で、年月（例: `2026年9月`）、今日、表示期間、設定を左、計画メニューと再計画を右端に配置。狭い場合は計画をアイコン化し、前後移動を表示メニューへまとめます。「今日」は背景・枠付きボタンです。
- 年月と上部ボタンを同じ高さで中央揃えにしました。ISO週番号は幅がある場合だけ年月の隣へ表示し、狭いホームではJST上に表示しません。時間帯はOSで取得した地域にも対応する略称で表示します。
- 今日の日付は赤い角丸で表示し、時間軸・列境界・終日予定・現在時刻ラベルを表示します。現在時刻に重なる時刻目盛りは隠します。再計画アイコンの中心を今日と翌日の境界へ配置し、ホバーインだけ回転します。ホバーアウトの戻りアニメーションはありません。右端でも見切れない余白を確保しています。この操作は複数日表示中でも今日を対象にします。
- 日・複数日・週の時間グリッドはShift＋ホイールまたは横方向のスクロールで隣の日付へ連続移動。時刻列と縦スクロール位置を維持し、月境界で予定を再取得します。
- 表示ショートカット: `T` 今日、`1` / `D` 日、`2〜9` 指定日数、`0` / `W` 週、`M` 月。Notion Calendarの実アプリの一覧で0=週を確認しました。入力中・ポップアップ・詳細表示中は反応しません。表示日数の変更時は現在時刻付近へ移動します。
- イベントは色付きの左線、タイトル、時間。自動配置は破線、固定済みは通常のカード、完了済みは薄い色とチェック。重複する時間は横並びに配置し、日をまたぐイベントは日付の境界で分割して表示します。
- タスクのドロップと既存予定のドラッグ移動は15分単位。つかんだ位置を維持し、別の日への移動にも対応します。手動移動は位置を固定します。
- 予定詳細の完了操作はその予定枠が対象です。元タスク全体の完了はタスク行・詳細から行います。同期済み外部予定は参照のみです。
- 上部に配置済みタスク数、予定時間、作業時間内の空き時間と占有バーを表示。時間の重複を除外し、空きの計算では睡眠・外部予定・移動バッファも除外します。作業時間の設定が取得できない場合は空き時間を表示しません。
- 習慣テンプレートはランチ、集中、運動、読書、振り返り、散歩。選択時はフォームを開くだけで、保存までDBを変更しません。
- 習慣が未登録なら「すべての習慣」「優先度別」に未登録状態と「習慣を作成する」「テンプレートを見る」を表示します。テンプレートは専用タブだけに表示します。
- 習慣の列は既存の配置条件から「必ず確保・時間帯あり・柔軟に配置」を表示。ReclaimのCritical等の保存優先度は追加していません。「時間帯あり」はFlexible内の条件表示であり、第三のスケジューリング優先度ではありません。
- 習慣設定の編集はID・作成日時を維持し、開いた後に変更されていれば上書きを拒否します。次回の計画から反映され、固定済みの予定を自動で書き換えません。

## カレンダーと計画の範囲

- 「7日間」は自動計画を作成する対象期間です。カレンダーの表示日数とは独立しており、計画メニューに1／3／7日間と対象日付を表示します。「未保存の提案を破棄」はプレビューのみの取り消しで、保存済みの予定は削除しません。
- Googleカレンダーの接続状況・取り込み対象・同期状況は設定の「カレンダー連携」へ移動しました。
- OAuthはデスクトップの設定から開始できます。OSのブラウザで認証し、トークンはOS資格情報ストアへ保存します。Webサーバーの起動は不要です。設定手順と検証範囲は[バックエンドの実装状況](backend-status-2026-09-21.md)を参照してください。
- 通常の計画はTask / Habit、保護された予定、同期済み外部予定、睡眠、作業時間、移動バッファを扱います。
- 提案だけではDBへ保存せず、「適用する」で前提の変更を検証して保存します。手動ドラッグはその場で保存します。
- 再計画も通常の自動計画と共通の経路を使います。現在時刻を含む計画では開始済みの枠を保持し、開始日・依存関係・分割配置を考慮します。
- 起動中は3分ごとに同期と7日間の計画提案を行います。新しい提案は上部から確認でき、適用とGoogleへの書き出しは明示操作で行います。定期処理は設定から停止できます。
- Google実アカウント接続、PostgreSQL接続、Googleへの書き戻しは今回未検証です。
- ガントの直接編集、通知からの履歴全体のUndo、会話による計画変更の承認フローは今回の範囲に含みません。

## 時間・計画の設定

- タイムゾーンは「OSに合わせる」「手動で指定」を選択して保存。新規設定は自動、既存設定は従来の手動指定を引き継ぎます。自動時はOSのIANA地域名を取得し、起動・フォーカス復帰・通常の定期読み直し時に追従します。入力中・計画案の確認中は変更を保留します。
- 自動設定はカレンダー表示と保存済み計画設定のタイムゾーンを合わせます。他の入力中の設定を勝手に保存せず、OS取得に失敗した場合は現在の値を保ち、設定画面に理由を表示します。手動指定の値も切替前の状態を保持します。
- 作業時間・睡眠時間・移動の余裕は画面幅に応じた3／2／1列のカード配置。入力欄に角丸と内側余白を設けています。

## 起動

リポジトリ直下から `cargo run -p mnema-desktop --locked`、または `scripts/dev-desktop.ps1`。
今回のGUIは `target/debug/mnema-desktop.exe` を使用しています。配布用の `dist` は更新していません。
