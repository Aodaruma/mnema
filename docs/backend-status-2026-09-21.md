# デスクトップ自動処理・計画制約・Google連携

更新日: 2026-09-21

## 今回の範囲

- デスクトップ単体での定期同期・計画提案
- 開始日、依存順序、タスク分割を守る計画生成
- デスクトップからのGoogle認証と、連携処理の信頼性向上

タスクの完了・削除に連動する予定の自動変更、計画のUndo、履歴の永続化、DBバックアップは今回の対象外。自動提案は保存済み予定を変更せず、適用とGoogleへの書き出しは利用者の明示操作で行う。

## デスクトップの動作

- 起動中は3分ごとに、選択したGoogleカレンダーを同期して7日間の計画を提案する。初期設定は有効。設定の「時間・計画」「カレンダー連携」から停止できる。
- タイマーはTokioランタイムで動き、画面描画やフォーカスに依存しない。アプリを終了した後の常駐サービスではない。OSスリープ中は処理せず、復帰時にタイマーが再開する。
- ネットワーク処理、計画生成、計画適用はGUIスレッド外で実行する。同期と手動の連携・計画処理は排他し、二重実行を避ける。
- 新しい提案は上部の「新しい計画案」から確認できる。手動レビュー中の提案を定期提案で上書きしない。
- 計画適用中は編集操作を一時的に止め、GUI内の同時編集との競合を防ぐ。適用時は既存のfingerprint照合も行う。
- タスク行の保存など、一部の従来のローカルDB操作は引き続き同期処理。今回、全DB操作を非同期化したわけではない。

## 計画制約

- タスクの開始日を、設定されたIANAタイムゾーンの日付境界として扱う。
- 未完了の先行タスクがすべて配置された後に後続タスクを配置する。依存先が存在しない・期間外・未配置・循環している場合は、後続も未配置とし理由を表示する。
- 連続した空き時間に収まらないタスクは、最小15分の枠に分割する。所要時間をすべて確保できない場合は部分配置しない。15分未満の短いタスクは連続枠に配置できる。習慣は分割しない。
- 分割された全枠の終了を依存判定に使う。一部が固定されているタスクは、その枠を残し、残りの所要時間を計画する。
- 現在時刻以降の提案では、既に開始した提案枠を保持する。開始済みの枠を過去へ配置し直さない。
- 分割された各枠に個別の安定したIDを維持し、再適用時のGoogleイベントの重複を防ぐ。差分にも分割された全枠を含める。

## Google接続の設定

Google CloudでCalendar APIを有効にし、OAuthクライアントの種類を「デスクトップアプリ」にする。既存のWebサーバー用クライアントとは種類が異なる。

Mnemaを起動するプロセスの環境変数に次を設定する。

```text
MNEMA_GOOGLE_CLIENT_ID=<デスクトップアプリのOAuthクライアントID>
MNEMA_GOOGLE_CLIENT_SECRET=<クライアント設定で発行されている場合>
```

設定後にMnemaを再起動し、「設定 → カレンダー連携」から「Googleに接続（読み取り）」を選ぶ。通常のブラウザが開くので、利用者がGoogleで認証する。デスクトップではリダイレクトURLの環境変数は不要で、127.0.0.1の一時ポートを使用する。

- OAuthはPKCEとstate検証を使用し、コールバック待機は3分で終了する。
- OAuthトークンはOS資格情報ストアへ保存する。DBやGUI設定ファイルには保存しない。
- 接続後の同期でカレンダー名の一覧が読み込まれる。取り込むカレンダーをチェックして「選択を保存」を押す。
- 書き出す場合は「Googleに接続（予定の書き出しも許可）」で認証し、「Mnema専用カレンダーを作成」を実行する。その後「保存済みの7日間の予定をGoogleに反映」で明示的に書き出す。
- 同期・書き出しの処理はデスクトップとRESTサーバーで共通化した。既存イベントへの競合検出（ETag）と、作成時の安定したイベントIDを維持する。
- 通信には接続・応答のタイムアウトを設け、一時的なHTTPエラー、429、Googleの403レート制限を最大4回まで再試行する。待機時間は段階的に増やし、通常の権限エラーは再試行しない。
- IDを指定できないカレンダー作成やOAuthコード交換は、重複・不確定な処理を避けるため自動再試行しない。
- 同期失敗時は自動計画を停止し、画面に失敗を表示する。古い・途中まで更新された外部予定を使って自動適用しない。REST側の既存workerにも同じ停止条件を追加した。

公式仕様: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)、[Calendar APIのエラー処理](https://developers.google.com/workspace/calendar/api/guides/errors)。

## 検証

- Rust workspace全150テスト通過、clippy（警告をエラー扱い）、format確認。
- 更新版GUIを起動し、ホーム・時間と計画・Googleカレンダー連携画面の表示を確認。
- SQLiteで開始日・依存順序・分割・再適用・安定ID・開始済み枠の保持・一部固定枠を含む計画を検証。
- バックグラウンド提案が予定を保存しないこと、二重実行を避けること、UIフレームが進まなくても定期workerが実行することを検証。
- ローカルHTTPサーバーで一時障害・レート制限の再試行、権限エラーと非冪等カレンダー作成の再試行禁止を検証。

実Googleアカウントの認証・OS資格情報ストアへの実保存・実APIへの書き出しは、利用者がOAuth設定を行った後に確認する。今回のテストではユーザーの実データ・外部カレンダーを変更していない。PostgreSQL実DBでの確認も未実施。
